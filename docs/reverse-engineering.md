# 《宿命篇》首轮逆向记录

## 样本与方法

以[已归档原版](../original/README.md)为样本，使用官方 [EasyRPG LCF2XML](https://easyrpg.org/tools/downloads/)读取数据库、地图树和地图，指定 CP936 中文编码。293 个输入均成功转换；输入原件哈希保持不变。本轮分析是数据和事件的静态解析，未反编译运行时，也未运行原游戏。

产出见[数据索引](../research/suming/README.md)与[汇总](../research/suming/summary.json)：291 张地图、2,677 个地图事件、4,139 个地图事件页；计入公共及战斗事件后，共 4,434 个索引页、27,017 条指令、5,931 个对话块、1,140 个直接地图跳转。指令编号均能匹配本次 liblcf 定义，直接跳转没有指向缺失地图文件。

数据库有 50 个角色槽、195 个技能槽、300 个道具槽、250 个敌人槽；其中很多是空白或占位。排除空名称和纯横线名称后，分别为 14、171、246、171 条；这仍不是“实际参与剧情”的判定。

## 启动流程与引擎版本

地图树配置的初始位置是地图 298、坐标 (7,4)。该地图的自动事件 `Map0298/Event0001/Page0001` 在开场声明中写明 Holiday、2005 年 6 月，以及 RPG Maker 2003 v1.09a；这比网页转载提供了更直接的版本证据。运行时 PE 版本资源是 1.0.9.1，两者属于不同版本标识，分别保留。

已核对直接跳转参数：

```mermaid
flowchart LR
  A[298 开场] -->|事件1 页1 指令30| B[5 杂院]
  B -->|事件2 页1 指令3| C[3 林-苏]
  C -->|事件4 页1 指令1| D[1 苏州城]
```

上述是开场附近的候选通路，事件页激活条件和操作过程仍需运行验证；不据此声称完成原版通关。

## 隐藏结局的实物线索

以下定位对应的原始指令已另存为[关键事件摘录](../research/suming/key-events.json)，方便逐项核对。

1. `Map0262/Event0011/Page0001` 的指令 71 比较变量 81（名称“支线”）与常量 12；指令 72 检查开关 961（名称“holiday”）；满足这段嵌套条件后，指令 73 打开开关 994。判断名称只是索引辅助，含义以 ID 和参数为准。
2. `Map0269/Event0002/Page0001` 也读取开关 994，可沿该事件追踪后续分支。此处尚未验证它与网页攻略所述全部支线的逐一对应。
3. `Map0272/Event0037/Page0001` 的指令 145 将角色 2（王飞霞）的饰品 ID 读入变量 12，指令 146 与道具 177（青龙碧血玉）比较；该分支的指令 150 进入敌群 224。
4. 敌群 224 的事件页 2 含额外对白，并在指令 49 打开开关 441（名称“结局”）。常规敌群 200 的事件页 1 也会打开开关 441，说明仅凭该开关名称不能区分两种结局。

角色属性操作 14 对应饰品 ID 的解释，依据 [EasyRPG Player 的解释器实现](https://github.com/EasyRPG/Player/blob/master/src/game_interpreter_control_variables.cpp)；条件比较与开关控制对照[事件解释器](https://github.com/EasyRPG/Player/blob/master/src/game_interpreter.cpp)。这些是静态证据，尚不能代替原运行时中的完整条件验证。

## 对续作设计的直接影响

- 应使用稳定的状态 ID 和命名空间，避免多个同名“结局”“开箱”开关混淆。
- 结局衔接不能只存一个布尔值；至少记录任务完成度、奖赏条件、关键装备、角色状态和选择。
- 对话、分支、公共事件和战斗事件都参与剧情，不能仅依靠台词文本还原演出。
- 本次原型仅借用已核实的一级气血、灵力与技能消耗；其回溯代价和战斗数值属于新增设计。
